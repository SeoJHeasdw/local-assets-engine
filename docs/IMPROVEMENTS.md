# 다음 개선 후보

2026-09-17 작업 종료 시점의 메모다. 추가 조사 없이 이번 구현·검증 과정에서 나온 항목만
정리했다. 다음 작업의 범위를 고를 때 참고하며, 아래 기능이 이미 구현됐다는 뜻은 아니다.

## 유지할 방향

- 1차 목표는 고품질 2D·3D 원본을 안정적으로 만드는 제작 도구다.
- 게임용 파일은 기본 생성에 포함하지 않는다. 실제 게임의 요구가 정해진 뒤 별도로 최적화한다.
- 원본과 이전 버전을 보존하고, 편집 결과는 새 버전으로 저장한다.
- 주 화면은 결과와 제작 동작에 집중한다. 상세 시간·메모리·로그는 기록으로 유지한다.
- 모델·해상도·면 수 등 품질 기본값 변경은 같은 입력·시드의 비교와 사용자 승인 후 진행한다.

## 먼저 확인할 항목

구현과 자동 검사는 완료했지만, 다음 수동 검증은 충분히 반복하지 않았다.

| 항목 | 확인할 내용 |
| --- | --- |
| 임시 편집 복원 | 앱을 완전히 종료했다 열어도 색상·문구·로고·이름이 복원되는지. 저장 공간 부족 시 안내도 확인 |
| 편집 후 다음 동작 | 미저장 편집에서 3D 변환·프리비즈·파일 내보내기를 누르면 최신 편집본이 전달되는지 |
| 긴 대기열 | 생성 중 편집 저장을 요청했을 때 대기 상태가 명확한지. 기다리는 중 닫기·중지·재시작·중복 클릭 확인 |
| 다양한 창 크기 | 작은 창·확대된 글자·키보드 조작에서도 생성·저장 버튼과 팝업에 접근 가능한지 |
| 여러 형태의 3D | 상자 외에 곡면·얇은 물체·깊은 홈·구멍이 있는 물체에서도 생성과 로고 투영이 안정적인지 |

현재 검증 근거: 실제 2D 생성·문구 편집·PNG 저장, 100만 면 상자의 색상·문구 편집·GLB 저장,
형상·UV·노멀 버퍼 보존 확인, Python 98개·앱 30개 테스트와 구조 검사 통과.
실제 예시는 `20260917-013016-e941`, `20260917-013659-c5f6`, `20260917-013916-5786` 작업에 있다.

## 게임 제작이 시작될 때

게임용 최적화는 현재 원본 생성 품질과 별도의 작업으로 둔다.

- 목표 엔진·플랫폼·카메라 거리·동시 표시 개수를 먼저 정한다.
- 원본의 윤곽을 유지한 경량 메시와 노멀맵 베이킹을 비교한다.
- 거리별 모델(LOD), 텍스처·메시 압축, 반복 배치 시 데이터 공유를 검토한다.
- 파일 용량만 보지 않고 실제 화면 차이·메모리·렌더링 시간을 함께 측정한다.
- 현재 과거 작업의 ‘게임용’ 파일을 최종 배포 최적화 완료본으로 간주하지 않는다.

[DESIGN_SYSTEM](DESIGN_SYSTEM.md), 채택 근거는 [DECISIONS](DECISIONS.md)를 따른다.
